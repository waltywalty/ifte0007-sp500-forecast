# Submission package

No final number, human approval, submitted report or binding release is declared here.

Required: report PDF (target 2,350–2,399 words, with a module maximum of 2,400 including narrative in tables and captions), evidence-only appendix maximum four pages / no new analysis, seven-minute slides plus three-minute questions, frozen demo/fallback, permitted evidence ZIP, final metadata/forecast, AI declaration and genuine contributions/checks.

GitHub supplements the original module route. Confirm marker access without changing visibility to bypass restrictions.

## Release checklist

1. Review [assessment map](../docs/assessment_map.md), rights and blockers.
2. Verify permitted final snapshot and actual required member approvals.
3. Use identical two-decimal value/instrument/target/cutoff/version throughout.
4. From 13 November noon, package sealed inputs only.
5. Build allowlisted ZIP tied to actual code commit.
6. Extract fresh and verify hashes/supported offline replay.
7. Record commit/tag/manifest/ZIP SHA-256; tag alone is not immutability.
8. Group checks all documents; real authorised person submits, target 16:00 / deadline 17:00.
9. Preserve assessed release; later outcomes separate.

A labelled sample/synthetic route explains what it proves and what empirical work cannot regenerate. It is not the actual final forecast or full historical reproduction.

## Final handoff from the group

- **Sources.** Provide the registered original inputs and receipts or record the decision on any separately documented source route. The [source guide](../docs/data_and_permissions.md) lists the fields needed to audit a manual check. Use the actual receipt and calculation times.
- **Review.** The coursework brief calls for group approval. The current project verifier implements this through two distinct human attestations. Each reviewer records their identity, actual review time, the snapshot hash, checks on instrument, baseline, factor inputs and arithmetic, and explicit approval. Record the approvals after the calculation and before the cutoff. This control is separate from owner review of the GitHub PR.
- **Release.** Keep the group identifiers, actual contributions and AI declaration with the assessment records. Confirm which files can go in the submission ZIP. Package one approved number and the exact evidence that supports it, then compare the report, slides and fresh offline replay against the same record.
